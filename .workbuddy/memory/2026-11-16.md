### 2. 四个真实 bug（都是靠实截/实测发现的）

1. **引擎盖立起来**（本轮最难的排查，绕了四轮）：
   - Blender 侧量出盖子是**水平**的（世界 z 0.61..0.81，铰链 0.79，坡度 2.8°）；
   - Unity 侧量出 `body_bonnet.001` 的 `worldRot = (321.7, 116, 180)`，车身是 `(270.3, 296, 0)`；
   - 中间我**误读了 `atan2` 符号**，把「-177°」当成「盖子翻了 177°」，主动旋转 177°，**反而把本来正常的盖子弄坏**；
   - 真因：FBX 导出对「父级有旋转 + 子级沿负轴偏移」做了镜像。bonnet 与 boot 在 Blender 里完全对称，却导出成不同旋转。
   - **修复**：`flatten_panels()` 把盖板网格直接挂到车根、删掉中间铰链 empty。
   - **教训**：Blender 侧与 Unity 侧数据不一致 = 中间有转换损失，不能只信一侧，也不能凭一侧读数推断另一侧。
2. **父子缩放不一致**：Blender `apply_unit_scale=True` 把单位缩放写进 FBX 根（×100）却不写进子节点 → Unity 里根 ×100、铰链 ×1。**修复**：关掉该选项 + 把归一化系数烘焙进网格顶点 + 所有对象 scale 归 1。
3. **检查点数被硬编码覆盖**（影响比赛判定）：`TrackPath.CheckpointCount` 写死 10，JSON 要 12。第 11 个检查点索引 `11*653/10=718` 越界，`Wrap` 折回起点，车在第二圈起点原地打转 18 秒。**修复**：改读 `TrackLayout.CheckpointCount`。**这正是「单一数据源」被硬编码打破的典型症状。**
4. **车库截图被护栏与对手车干扰**：远处对手车尾翼与赛道广告牌横在车身上方，像浮空零件。我一度误判为玩家车 bug。**修复**：截图前隐藏对手车 + 抬高相机。

### 6. 过程教训

- **先用 Python 把几何调到合规，再进引擎**：赛道约束全是纯几何量，Python 里毫秒级，Unity 里试错要 3–4 分钟一次构建。
- **截图里的异常先确认归属**（见 bug 4）：用 `execute_code` 探测 Unity 里的世界坐标、父子关系、实测包围盒，比反复看截图快且准。
- **`Renderer.bounds` 是单个 `Bounds` 结构体，不能 foreach**——要用 `localBounds` 的 8 个角点。
- **离线 lint 增强**：新增「foreach 遍历 GameObject / Component」检查（`tools/cs_lint.py`），这类错误 Unity 要等完整构建才发现。
- 遥测 1 秒采样会漏掉「终点跨越」那一帧；`race_time ≈ 2 × best_lap` 可交叉验证圈数，别只看 CSV 的圈数字段。

### 7. GLB→FBX 转换管线修复（06:35 交付包）

起因是复盘车库实截发现三处零件跑错位置：CityCar / HotHatch / ThreeDoor 的**后尾门伸到车尾外 0.9 m**、**车轮塌到原点**、**车身浮空 28 cm**。真凶不是模型，是 `tools/prepare_hd_fleet.py` 里三条叠在一起的转换 bug：

1. `bpy.ops.object.transform_apply` 作用于**整个选择集**，而 GLB 导入后全部物体默认选中 → 同一个变换被反复施加。
2. 同一操作对**带父级的子物体**会把父级变换折进结果 → 铰链子物体（bonnet / boot / glass）落点不可靠。
3. 归一化后的「位置缩放」循环遍历了**全部对象**，把网格 `location` 又乘了一遍系数 → 重复缩放。

修复要点：

- 新增 `bake_basis()`：用 `bmesh.ops.transform` 把缩放/旋转**烘焙进顶点**，物体变换重置为纯平移；结果与选择状态、父级变换无关。**这是 Blender 里处理父子层级变换的可靠姿势**，优先于 `transform_apply`。
- 位置缩放只做一次且只作用于网格；empty 循环只处理 empty。
- 卸父级必须显式写回世界矩阵：`world = o.matrix_world.copy(); o.parent = None; o.matrix_world = world`（否则物体落回自身局部变换，轮子归零）。
- 新增 `clip_interior_to_roof()`：interior 网格（座椅头枕）高出车顶 12 cm → 删掉超出车顶线的顶点，车顶上的黑方块消失。
- 「自动闭合尾门」改成**只读校验** `check_tailgates()`：面板超出车体 0.35 m 就让转换失败，不许偷偷挪几何。
- 保留 `tools/inspect_fbx_parts.py`（Blender 列出 FBX 每个网格的世界包围盒）——判断零件跑错地方最快的手段。

结果：10 款 HD 车车长精确 4.53 m、尾门结构与正常的 ElectricHatch 一致、四轮归位、车高回到合理区间（CityCar 1.93 / HotHatch 1.62 / SportsCar 1.18 m）。

交付包 `build_20261116_nova14_fix.out`：`Succeeded / 0 error / 0 warning` / 223,906,099 B；`-racetest` `05:41.551 / 最快圈 02:50.736 / 1 of 4`、检查点 24 次推进、圈数 0→1→2、最高 106.6 km/h；`-nitrotest` overdrive **191 帧 / 4.68 s / FOV 66.22°**；`-collisiontest` 抖动 **0.0438 m** + 对手推挤 **0.05 m**；`-garagedrive` 连换 3 次物理不变、行驶 54.1 m；`-padmaptest` **29/29**。
